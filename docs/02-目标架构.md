## 1. 四个独立物，各自有边界

| 物 | 放在哪 | 谁维护 | 生命周期 | 进不进目标项目 |
|---|---|---|---|---|
| **skills 仓库** | git 单仓 | 作者 | 随 commit 演进 | ❌ 只同步产物 |
| **runtime** | 项目 `.agents/routing/` | 生成，不手改 | 随 lock 更新 | ✅ 3 个文件 |
| **skills** | 项目 `.agents/skills/` 或全局 | 作者 | 随 lock 更新 | ✅ 软链/复制 |
| **authoring** | 源仓 `tools/panel/` | 作者 | 独立发版 | ❌ 永不 |

判断标准只有一句：**目标项目只需要“读”，不需要“编辑”。** 任何需要写盘、需要 Electron、需要 node_modules 的东西，一律留在 ①④。

## 3. 两份图：这是最关键的改动

### 现在的问题

`SKILL_ROUTING.md` 一份文件同时承担两个职责：

- **全集目录**：我有哪些技能
- **项目路由表**：这个项目该用哪些

复制到新项目后，前半段必然错（技能没装），后半段也必然错（指向不存在的路径）。

### 拆开之后

```
routing/graph.json          全集，作者维护
      │
      │  bootstrap / sync 时跑一次生成器
      ▼
.agents/routing/SKILL_ROUTING.md    子集，只含本项目真实存在的 skill
```

生成器做三件事：

1. 遍历 `graph.json.skills`，检查 `path` 解析后是否存在
2. 过滤掉不存在的、`status != active` 的、`capabilities.json` 未启用的
3. 重写机器块，并把 `sourceRef: {repo, sha}` 写进头部

于是：

- `--validate` 从“语法检查”升级为“语法 + 落地检查”，缺 skill 直接 **FAIL**
- `--annotate` 只可能推荐本项目真有的 skill
- plan 里的 skill 标注可以追溯到某个 commit

## 4. 锁文件格式

`.harness/skills.lock`

```json
{
  "repo": "git@github.com:your-org/harness-skills.git",
  "sha": "9f3c1a7",
  "ref": "main",
  "syncedAt": "2026-11-17T14:00:00+08:00",
  "cacheDir": "~/.cache/harness-skills/9f3c1a7",
  "graphVersion": 1
}
```

规则三条：

1. **会话开始同步一次**，不是每次调用前。锁定 `sha` 后本次会话不再变。
2. 首次接入写 lock；之后只在显式执行 `harness:sync` 时更新。
3. 联网失败 → 用缓存继续，只在状态行提示 `skills: 缓存 <sha>（离线）`。

`.harness/capabilities.json`（可选，缺省 = 全部 active）

```json
{
  "enabled": ["figma-long-page", "echarts", "tailwind-design-system"],
  "disabled": ["thymeleaf"]
}
```

用途：新项目不必装全部 14 个技能，只装用得上的；`enabled` 之外的 skill 连同步都跳过。

## 5. 三条数据流

### A. 接入（新项目，一次性）

```
/harness install 或 bootstrap-harness.ps1
  ├─ 读 skills.lock（没有则 fetch 最新 tag）
  ├─ 拉缓存 ~/.cache/harness-skills/<sha>/
  ├─ 链接 .agents/skills → 缓存 skills/（软链；不支持则复制）
  ├─ 生成 .agents/routing/ 三个文件（子集图）
  ├─ 写 .harness/{skills.lock,capabilities.json,version.json}
  ├─ 写 AGENTS.md 首屏强指令（L0 触发）
  ├─ 装 scripts/harness/ + docs 骨架
  └─ 跑 router --validate（失败则整体失败，不打印“装好了”）
```

### B. 需求（每次新需求）

```
用户描述需求
  ├─ agent 读 AGENTS.md（L0）→ 自动加载 harness-run
  ├─ create-demand 建模块
  ├─ ★ Mode B 预判：node .agents/routing/router.mjs "<需求原文>"
  │     └─ 命中结果写进 requirements 头部：> 预判 skill: echarts(0.85)
  │     └─ 命中项在 capabilities 之外 → 当场提示“本项目未启用 X，是否先装”
  └─ brainstorming → spec
```

### C. 计划（每个模块）

```
writing-plans 收尾
  ├─ ★ Mode A 标定：router.mjs --annotate plans/01-dev-plan.md
  ├─ 人工复核，逐 Task 写 `> **Skill:** xxx · 置信度 0.85 · 低风险`
  ├─ harness:check（★ 新增：缺 `> **Skill:**` 行 → 警告）
  └─ P3 → READY_TO_DEV → 开发
```

## 6. 三级触发：把 `/harness` 变兜底

| 级 | 时机 | 载体 | 确定性 |
|---|---|---|---|
| **L0 常驻** | 每次会话 | 项目 `AGENTS.md` 首屏 10 行：改 `src/` 前必须加载 `superpowers-harness-run` | 高（文件强制读） |
| **L1 需求预判** | create-demand 之后 | Mode B 自由文本匹配，结果写 requirements | 高（脚本化） |
| **L2 计划标定** | writing-plans 收尾 | Mode A `--annotate` + 门禁校验 | 高（可机械检查） |
| 兜底 | 用户显式输入 | `/harness <需求>` | — |

`/harness` 从“唯一入口”降为“重放/救场”；`AGENTS.md` 是新的默认入口。

## 7. 编辑器：静态站 + PR

```
panel（Vue + Vite，纯前端）
  ├─ 打开：读仓库里的 routing/graph.json（HTTP GET 或拖入文件）
  ├─ 编辑：拖节点、改分类、改 triggers（现有交互不变）
  ├─ 校验：浏览器里跑 schema 校验 + 技能存在性（用 GitHub Tree API）
  └─ 保存：提交 PR（GitHub OAuth），不直写
```

- 删掉 `server.mjs`、`electron/`、`release/`、`_baota-upload/`
- 不再需要 `pick-file` / `list-dir`（浏览器 File System Access API 可替代，且非必需）
- 改动天然可评审，与 skills 仓库的 CI 校验打通

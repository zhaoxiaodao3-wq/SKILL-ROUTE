# 03 · 落地路线

> 前提：**v2 与现有目录并存**。每一步都可单独验证、可单独回滚，现有流程始终可用。

---

## 1. 总览

| 阶段 | 目标 | 工期 | 是否改变现有行为 |
|---|---|---|---|
| **P0 止血** | 让安装不再静默出错 | 半天 | 是（只改 bootstrap + routing 目录归属） |
| **P1 无感** | 新项目自动进流程 | 1–2 天 | 是（新增 AGENTS.md 常驻指令） |
| **P2 可信** | 路由错了能被发现 | 2–3 天 | 是（新增门禁警告） |

顺序不能换：P0 没做完就做 P1，等于把自动流程建在一个会漏装的安装器上。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 历史 plan 全都没 skill 标注 | 2.3 一上线，几十个模块同时亮警告 | 门禁只检查**本次新增/修改**的 plan（按 git diff），历史不追溯 |
| 软链在 Windows 需要权限 | `.agents/skills` 链接失败 | 软链失败自动降级为复制，并在 `version.json` 记 `mode: copy` |
| 缓存 sha 与同事不同 | 两人路由结果不一致 | 把 `repo@sha` 写进 plan/archive 头部，复盘时可见 |
| 技能仓库与源码仓同时改 | 序列号错乱、双 PR | 技能仓库独立 tag（`v1.x`），源码仓只 pin tag |
| 编辑器改完没人评审 | 图被改坏 | 只走 PR + CI label，禁止直推 main |

## 6. 迁移期并存策略

```
现在                                 v2 落地后（并存期）
.agents/routing/  （旧，四合一）  ←→  保持不动，旧命令继续可用
.agents/skills/   （旧副本）      ←→  保持不动
              新增：.harness/  + 生成脚本 + tools/panel/
```

三条规则：

1. **旧的一律不改**，包括 `docs/superpowers/` 与历史模块；新流程只对新建模块生效
2. 生成器写 `.agents/routing/` 前先备份到 `.harness/backup/<时间戳>/`
3. 切换开关：`.harness/config.json` 里 `"mode": "legacy" | "v2"`；出问题改回 `legacy` 立即止血

---

## 7. 明确不做

- ❌ 不重写 `router.mjs` 的匹配算法（现在够用，只是缺存在性校验）
- ❌ 不重做需求文档体系（`docs/superpowers/` 结构保留）
- ❌ 不做“每次使用前同步远程”
- ❌ 不把编辑器部署成有状态服务
- ❌ 不在 P0 阶段碰任何现有文件（P0 只动源仓里的脚本与新增 `tools/`）

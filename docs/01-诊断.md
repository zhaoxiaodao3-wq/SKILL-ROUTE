# 01 · 诊断：现在这套怎么转，卡在哪

> 本文只描述现状与证据，不提方案。方案见 [02-目标架构.md](./02-目标架构.md)。

## 1. 一次需求实际发生了什么

```
用户："把首页改深色"
  │
  ├─ 用户（或 .cursorrules 片段）想起要打 /harness
  │     └─ 没想起来 → 直接改 src/，流程完全跳过
  │
  ├─ agent 加载 superpowers-harness-run
  │
  ├─ Step 0  pnpm harness:status --match "首页"
  │     └─ 输出阶段：NO_MODULE / NO_SPEC / NO_PLAN / READY_TO_DEV
  │
  ├─ 分档：轻量 / 标准 / 全量
  │
  ├─ Step A  create-demand.ps1  → docs/superpowers/{ver}/{type}/{模块}/
  ├─ Step B  brainstorming      → specs/01-dev-spec.md      （P2 暂停）
  ├─ Step C  writing-plans      → plans/01-dev-plan.md      （P3 暂停）
  │     └─ 跑 router.mjs --annotate，把建议 skill 写进每个 Task
  ├─ Step D  开发（先 harness:check）
  └─ Step E  一致性自检 → 还原度自检 → archive → validate
```

其中有三个关键节点：**谁能进来（入口）**、**谁做决定（路由）**、**谁兜底（门禁）**。目前分别是“靠人”“靠概率”“靠自觉”。

## 2. 运行时其实很轻

- [SKILL_ROUTING.md](../.agents/routing/SKILL_ROUTING.md)：680 行，其中 `<!-- SKILL_GRAPH_START -->` 与 `END` 之间是机器块 JSON——14 个 skill、13 个分类、全局阈值（`minConfidence 0.7` / `maxSkillsPerPlan 5` / `autoActivateRiskLevel low`）
- [router.mjs](../.agents/routing/router.mjs)：480 行，零依赖，只用 `fs` / `path`，四个模式：`--annotate` / `--list` / `--validate` / 自由文本

**两个文件就够跑，这是好消息**——v2 不需要重写引擎，只需要换分发方式。

## 3. 七个洞的证据

### 洞 1：安装路径写死

[bootstrap-harness.ps1:143-146](../.agents/skills/superpowers-harness/scripts/bootstrap-harness.ps1#L143-L146)

```powershell
foreach ($candidate in @(
    (Join-Path (Split-Path $AgentsSkills -Parent) "routing"),
    "E:\code\frontend-local\.agents\routing"     # ← 写死本机路径
))
```

换机器后这条命不中，走 [第 174-176 行](../.agents/skills/superpowers-harness/scripts/bootstrap-harness.ps1#L174-L176) 的 `[警告] 未找到 routing 源，跳过`——但脚本末尾仍打印 `Skill 路由: .agents\routing\SKILL_ROUTING.md`。

### 洞 2：图推荐不存在的 skill

每个 skill 条目的 `path` 都是相对路径（如 `"path": "../skills/superpowers-harness-run"`），指向**本仓技能集**。
而 `router.mjs` 里 `fs.existsSync` 只用于配置文件、缓存、路由 MD——**从不检查 skill 目录是否存在**。
结果：`--annotate` 会自信地推荐一个目标项目根本没有的 `figma-long-page`，置信度还很高。

### 洞 3：技能依赖闭包没装全

`superpowers-harness-run` 声明 `after: [superpowers-demand-workflow, brainstorming, writing-plans]`。
bootstrap 装的是 `superpowers-harness` + `superpowers-harness-run` 两个技能目录，加上 `demand-workflow` 的 **scripts/docs**（不是技能本体）。
`brainstorming` / `writing-plans` 依赖插件——插件没装就是空指针，但流程照样往下走。

### 洞 4：不喊就不走

`/harness` 是显式命令；description 匹配是概率行为。
项目级兜底是 [cursorrules.snippet](../.agents/skills/superpowers-harness/references/cursorrules.snippet)（14 行），只对 Cursor 生效；DSH 侧没有等价常驻指令。

### 洞 5：门禁不校验路由

`validators/` 下 grep 不到 `SKILL_ROUTING` / `Skill:` / `annotate`。
plan 一个 skill 都不标，`pnpm harness:check` 照样绿。
所以洞 4 一旦发生，**没有任何机制知道**。

### 洞 6：四套副本

同一批技能存在于 `.agent/skills`、`.agents/skills`、`.claude/skills`、`.cursor/skills`。
改一处要同步四处；skill 自己的 SKILL.md 里也留了警告（`superpowers-harness-run` 第 16 行）。

### 洞 7：编辑器跟着分发

`routing/` 下同时有 `electron/`、`panel/`（Vue+Vite）、`server.mjs`、`release/win-unpacked`、`_baota-upload/`、两套 `node_modules`，合计约 2 万个文件。
`.gitignore` 只有 7 行（忽略 `.env` 与 `.claude/settings.local.json`），没有隔离它们。

## 4. 一个容易被忽略的静默失败

[router.mjs:479](../.agents/routing/router.mjs#L479)

```js
const isMain = process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href;
if (isMain) main();
```

当脚本经 junction / 相对路径 / 符号链接调用时，两串 URL 字符串不相等 → `main()` 不执行、**不报错、直接退出 0**。
你自己的 plan 里已经有四五次记录（例如 `V1.6.0/fix/A2序号内容单行居中` 写着“CLI 未进 main，改用 import 等价跑通”）。
无感接入最怕这种“看起来成功”的失败。

## 5. 小结：病根不是缺工具，是缺边界

| 缺的边界 | 现在混在一起的东西 |
|---|---|
| 生命周期 | 运行时数据 vs 作者工具 vs 打包产物 |
| 作用域 | 全局技能全集 vs 本项目的可用子集 |
| 责任 | 谁来触发 vs 谁来校验（现在都靠同一个 SKILL.md 文本） |

v2 的三件事正好对应这三条边界：分目录、拆图、分触发与门禁。

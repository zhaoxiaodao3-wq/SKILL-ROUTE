## 3. 四条安全规则

1. **先备份后移动**：每次执行前把受影响的目录打包到 `harness-v2/backup/<时间戳>/`（或 `git stash`），移动只在工作区做，不碰历史。
2. **一次只做一列**：按 P0 → P1 → P2 走，每阶段结束时旧流程仍可用；不要跨阶段混做。
3. **生成的不要手编**：项目内 `.agents/routing/SKILL_ROUTING.md`、`.harness/*`、`AGENTS.md` 都是生成物，手改会被下次 sync 覆盖——改就去改 `graph.json` / 模板。
4. **可回滚**：`.harness/config.json` 里 `"mode": "legacy" | "v2"`，出问题切回 `legacy`，旧目录原封不动。

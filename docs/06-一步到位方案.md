# 06 · 一步到位方案（终态设计）

> 不再分“先保存、再关联线、再 AI”。先定终态，所有零件一次对齐，再按这个骨架落地。

---

## 1. 一句话

**打开一个链接 → 改路由 → 保存即入库 → 所有项目自动用最新；AI 只在你点它的时候出现。**

四个东西，各司其职：

```
┌─────────────────────┐      ┌──────────────────────┐
│ 仓库（真相）          │      │ 网关（唯一写入口）     │
│ skills/              │◀────▶│ Node 服务             │
│ routing/graph.json   │ git  │ 校验 → commit → push  │
└─────────┬───────────┘      └──────────┬───────────┘
          │                              │ /api/*
          │ 读                           │
┌─────────▼───────────┐      ┌──────────▼───────────┐
│ 项目（消费者）        │      │ 面板（编辑器）         │
│ harness 技能包       │      │ 静态站 + 画布         │
│ ensure / sync        │      │ 打开即用              │
└─────────────────────┘      └──────────────────────┘
```

---

## 2. 数据模型（终态）

**仓库里只有一份**：`routing/graph.json`

```json
{
  "version": 2,
  "categories": [{ "id": "cat-fe", "name": "前端", "parentId": "cat-dev", "color": "blue" }],
  "skills": [{
    "id": "echarts", "name": "echarts", "categoryId": "cat-fe-viz",
    "path": "../skills/echarts",
    "description": "ECharts 图表：初始化、主题、大数据、响应式",
    "triggers": ["echarts", "图表", "大屏"],
    "antiTriggers": ["其他图表库"],
    "tags": ["可视化"],
    "requires": [], "after": [],
    "riskLevel": "low", "status": "active"
  }],
  "globalConfig": { "minConfidence": 0.7, "maxSkillsPerPlan": 5 }
}
```

字段收敛原则：

- 只保留**能影响路由**的字段（triggers / antiTriggers / tags / path / status）
- `userDescription` 和 `systemDescription` 合并成一个 `description`
- 新增 `antiTriggers`（原来叫 unsuitableConditions），面板上叫“反例”

**项目覆盖**（可选）：项目里 `.harness/routing.override.json`

```json
{ "disable": ["thymeleaf"], "addTriggers": { "echarts": ["BI 看板"] } }
```

合并顺序：全局 graph → 项目 override → 生成给 router 用的子集。

## 3. 网关 API（4 个端点，就这些）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/graph` | 返回 `{ graph, sha }`（sha 用于乐观锁） |
| PUT | `/api/graph` | 校验 + commit + push，body `{ graph, sha }`；sha 不匹配 → 409 |
| GET | `/api/bundle?ref=main` | 给项目用：`{ sha, graph, skillsIndex }`，带 ETag |
| GET | `/install` | 新电脑一条命令装技能包（返回 PowerShell/bash 脚本） |
| POST | `/api/ai` | 代理模型调用，密钥留在服务端；三种任务见 §6 |

**PUT 的校验顺序（任一失败都不写盘）：**

1. JSON 合法、`version` 匹配
2. 每个 skill 的 `path` 在仓库里存在
3. category 的 `parentId` 无环、无悬空
4. id 唯一
5. 触发词重复只报 **warning**（允许，但要显式确认）

校验通过 → `git add routing/graph.json` → commit（消息含改动摘要）→ push → 返回新 sha。

冲突（别人先改了）→ 409 + 最新 sha，面板提示“重新加载后重试”，不覆盖。

## 4. 面板（终态功能集）

**一屏四区：**

```
顶栏：搜索 · 保存状态（未保存/已保存 sha）· 版本 · AI 体检
左：画布（树 + 关联线）
右：抽屉（名称/分类/描述/触发词 chips/反例/冲突/AI 建议）
底：试一句 + 命中解释 + 无命中时“建议加词”
```

**画布必须有的三样：**

- 冲突边：触发词完全相同的两个 skill 之间红色虚线（点线看共用词）
- 依赖边：`requires` / `after` 灰色箭头
- 节点徽标：触发词数、冲突数、`status=deprecated` 变灰

**交互沿用 simple-mind-map**（Tab/Enter/F2/Delete/拖拽/撤销/搜索已通），只加：

- 右键菜单：新建分类、新建 skill、删除、复制、移动到…
- `Ctrl+S` 保存（走 PUT，不是下载）
- 保存前 diff：改了哪些节点、加了哪些词，确认才提交

## 5. 项目侧（harness 技能包）

```
ensure:
  1. GET /api/bundle → 拿 sha
  2. 写 .harness/routing.json（子集，含 antiTriggers）
  3. 写 .harness/routing.lock（sha + 时间）
  4. 合并项目 override
  5. 网络失败 → 用本地缓存，状态行标「离线 · sha abc123」

sync（新增命令，可选）:
  比对 lock 里的 sha 与远端，落后才更新；不自动改工作区
```

关键：**项目不 clone 技能仓**，只拉 `bundle`（几百 KB 的 JSON + 索引）。技能正文通过 `path` 指向用户级技能目录，缺了就在面板里标红。

### 5.1 换电脑：什么会跟、什么不会

| 东西 | 换电脑后 | 怎么保证 |
|---|---|---|
| 面板 | 打开网址就有 | 无状态，天生同步 |
| 路由图 / 技能正文 | 在服务器上 | 天生同步 |
| 技能包（harness 本身） | 新机器上没有 | `curl -s https://harness.域名/install \| sh` 一条命令装到 `~/.agents/skills/harness` |
| 项目里的需求文档 | **会丢**（现在被 gitignore 了） | 改成提交：只忽略缓存，不忽略文档 |
| 项目里的 `.harness` 配置 | 忽略，重跑 `ensure` 自动生成 | 配置是默认值 + 少量覆盖，可重建 |
| AI 密钥 / 登录密码 | 在服务器 | 客户端不留任何密钥 |

**gitignore 规则要改**（这是之前“全部忽略”的必要修正）：

```gitignore
# >>> harness (managed) >>>
/.harness/*
!/.harness/docs/
/.harness/docs/.tmp/
# <<< harness (managed) <<<
```

含义：**需求文档（`.harness/docs/`）跟着项目走**，换电脑、clone 别人都还在；缓存、备份、锁文件仍然不提交，重跑 `ensure` 即可再生。

### 5.2 新电脑上手（三步）

```bash
# 1. 装技能包（全局一次，所有项目可用）
curl -s https://harness.你的域名/install | sh

# 2. clone 项目（需求文档在 .harness/docs/ 里，跟着来）
git clone <项目>

# 3. 在项目里拉最新路由（可跳过，ensure 会自动拉）
node ~/.agents/skills/harness/scripts/harness.mjs sync
```

`sync` 比对服务器上的 sha 与本地 `routing.lock`，落后才更新；断网就用缓存并提示。

## 6. AI 的三个入口（全部走“建议 → 采纳”）

| 入口 | 输入 | 输出 | 落库方式 |
|---|---|---|---|
| 生成触发词 | 单个 skill 的 description + 正文摘要 | 10–15 个中文触发词 + 3 个反例 | 面板里逐条勾选，采纳才进 draft |
| 冲突体检 | 全量 graph + 20 条样例句子 | “这两个抢同一句”“这个 skill 谁都触发不到” | 生成报告，点击跳到节点手动改 |
| 无命中补词 | 试一句的输入 + 未命中的 top3 | “建议给 X 加『…』” | 一键写入 draft（仍要保存才生效） |

服务端 `/api/ai` 统一收 `{ task, payload }`，模型 key 放服务端环境变量，面板永不接触。

## 7. 部署（你已有的域名 + 服务器）

```
nginx (TLS + basic auth)
├─ /            → /srv/harness-panel/dist（静态）
└─ /api/*       → 127.0.0.1:7001（Node 网关，systemd）
                     └─ /srv/harness-skills（git 副本，deploy key 单仓写权限）
```

- 备份：git 本身 + 每日 `git bundle` 到备份目录
- 回滚：`git revert` 即可，面板“历史”按钮列出最近 20 次提交
- 升级面板：替换 `dist/`

## 9. 验收（做到这些就算一步到位）

- [ ] 面板改一个触发词 → 点保存 → 3 秒内仓库出现 commit，顶栏 sha 更新
- [ ] 两个人同时改 → 后者收到 409，不覆盖前者
- [ ] 把 skill 的 path 改成不存在的目录 → 保存被拒，面板标红该字段
- [ ] 任意项目 `ensure` → 拉到同一个 sha；断网再跑 → 用缓存并提示离线
- [ ] 试一句「按 Figma 还原这个长页面」→ 命中列表带原因，无命中时给建议
- [ ] 面板上能看到冲突红线，点击能看到共用词
- [ ] **换电脑**：新机器 `curl /install | sh` + `git clone` 项目 → 文档还在、技能包在、打开面板能看到同一份路由

## 10. 工作量（一次性做完，不再分批）

| 包 | 内容 | 估时 |
|---|---|---|
| server | 4 个端点 + 校验 + git 提交 + AI 代理 | 1.5 天 |
| panel | 保存/409/diff/右键菜单/冲突线/AI 建议面板 | 2 天 |
| skill | `ensure/sync` 拉 bundle + lock + override 合并 | 1 天 |
| 部署 | nginx、systemd、备份、basic auth | 0.5 天 |

合计约 5 个工作日，可以一个人做完；每一步都能单独跑通，但数据模型是终态，不用返工。
